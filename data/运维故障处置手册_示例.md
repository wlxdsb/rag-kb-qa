# 运维故障处置手册（示例知识库）

> 本文件为**示例知识库**，用于演示 RAG 问答流程。内容为虚构的通用运维经验，
> 请替换/追加为你自己的真实资料（课程资料、领域手册、故障 SOP 等）。

## 1. GPU 显存不足（OOM）

现象：训练或推理任务报 `CUDA out of memory`。

处置步骤：
1. 用 `nvidia-smi` 查看显存占用与残留进程。
2. 清理僵尸进程：`kill -9 <pid>`。
3. 降低 batch size，或开启梯度累积（gradient accumulation）。
4. 推理场景可开启量化（如 INT8 / FP16）降低显存占用。
5. 仍不足时申请扩容，或改用多卡并行。

## 2. 磁盘写满（No space left on device）

现象：服务写入失败，日志提示 `No space left on device`。

处置步骤：
1. `df -h` 定位写满的挂载点。
2. `du -sh /*` 逐层排查大目录。
3. 清理过期日志与临时文件，并配置日志轮转 `logrotate`。
4. 必要时扩容，或把冷数据迁移到对象存储。

## 3. 推理服务时延升高

现象：TTFT、TPS 指标劣化，请求开始排队。

处置步骤：
1. 检查 GPU 利用率与显存是否成为瓶颈。
2. 查看是否触发了限流 / 熔断。
3. 优化批处理大小（batch）与并发数。
4. 启用 KV Cache 复用，降低重复计算。

## 4. 向量检索召回不准（RAG 答非所问）

现象：知识库问答答非所问，召回内容与问题不相关。

处置步骤：
1. 检查文本切分粒度，块过大或过小都会影响召回质量。
2. 调整 top-k 与相似度阈值。
3. 引入重排序（rerank）模型对候选排序。
4. 更换更贴合领域的中文 embedding 模型。
